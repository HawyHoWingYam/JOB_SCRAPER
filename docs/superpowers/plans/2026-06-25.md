# 任務目標
請使用前端自動化測試工具（善用各類 MCP 與內置 Skills）對 OfferToday 平台進行深度爬取測試與可用性驗證。若過程中遇到 Bug 或報錯，請進入「修改 -> 測試 -> 驗證」的閉環迭代，直到結果完全符合預期為止。

# 核心執行架構（分階段執行）
1. Phase 1：按分類爬取 Job ID。
2. Phase 2：根據 Phase 1 爬取到的 Job ID，進一步爬取詳細的 Job Details。

# 技術限制與工具調配
- 【有頭模式】必須全程開啟有頭模式（Headed Mode）進行測試與視覺化觀察。
- 【無限滾動處理】OfferToday 的職位列表需要持續 Scroll Down 才會加載。請精準控制滾動邏輯，確保加載穩定。
- 【多模態輔助】若在自動化過程中遇到驗證碼、圖形檢測或需要圖像識別的場景，請立即呼叫 Sub-agent `qwen3.7plus` 協助閱讀圖像並返回結果。
- 【人工介入機制】如果遇到極其複雜、Agent 無法自動通過的防爬蟲檢測（類似 ctgoodjobs 的情況），請暫停並提示我進行「手動過檢測」，待我完成後你再繼續執行。

# 測試邊界與驗證指標（核心測試案例）
1. 【全行業覆蓋】：必須遍歷測試過所有 Target Sectors（目標行業）。
   ※ [請在此處填入你的目標行業清單，例如：IT、Finance、Marketing，或寫「請自行從前端選單抓取所有分類」]
   
2. 【滾動深度與 Job ID 唯一性驗證】：
   請分別測試加載深度相當於「5頁、10頁、15頁、20頁、25頁、30頁」的數據量（註：由於是無限滾動，請將每頁定義為「成功加載至少 10 個不同的 Job ID」）。
   
3. 【數據查重】：
   測試時需嚴格比對並記錄不同深度下爬取到的 Job ID。驗證是否隨著滾動加載，拿到的 Job ID 都有所分別。
   
# 輸出報告要求
測試完成後，請輸出一個結構化的驗證報告，包含：
- 測試的 Sectors 列表
- 各滾動深度下（5/10/.../30頁）爬取到的總 Job ID 數量與去重後的唯一 ID 數量
- 錯誤修正記錄（如果有調整過代碼）
