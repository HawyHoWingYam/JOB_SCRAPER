# Business Domain: Search and Retrieval

## Current Responsibilities

Search and retrieval serve job browsing, filters, export, semantic/hybrid search, embeddings, and related job recommendations.

## Current Implementation Map

- Public API: `backend/app/api/jobs.py`, `filters.py`, `recommendations.py`
- Internal services: `backend/app/retrieval_main.py`, `recommendation_main.py`
- Retrieval service: `backend/app/services/retrieval_service.py`, `retrieval_client.py`, `recommendation_client.py`
- Search logic: `backend/app/search/*`
- Frontend: `frontend/src/components/JobBrowser.jsx`, `JobDetailModal.jsx`, `FilterPanel.jsx`

## Data and Control Flow

Lexical search is handled locally by the main backend. Semantic and hybrid modes proxy to `retrieval-api`. Related jobs proxy to `recommendation-api`. Embedding rows are persisted in `job_embeddings` and generated by the embedding worker.

## Known Gaps or Risks

- Search behavior changes depending on whether worker-profile ML services are running.
- Export mirrors retrieval mode, so non-lexical export depends on the retrieval side service.
- Frontend scope layering is sophisticated and requires backend validation details to remain readable.
- Semantic/hybrid modes can surface sidecar 503s instead of being disabled by advertised capability state.
- The final semantic request contract still relies on fallback behavior between lexical backend code and the retrieval sidecar.

## Optimization Backlog

- Add `/api/v1/capabilities` coverage for lexical, semantic, hybrid, export, and recommendation availability so the UI can disable unavailable modes before request time.
- Make lexical fallback explicit in `JobSearchRequestSchema` and response metadata, including whether a semantic/hybrid request degraded.
- Align export metadata with search metadata so exported files capture active filters, retrieval mode, fallback state, and sidecar version.
- Re-evaluate whether `retrieval-api` and `recommendation-api` should remain separate processes or share one ML boundary with consistent health/readiness.

## Follow-up Audit Questions

- Should search capabilities be advertised through an API endpoint so the UI can disable unavailable modes?
- Should retrieval fallback behavior be explicit per request?
- Should related jobs and semantic search share one internal ML service boundary?
