# SDK / semantic-validation scout (IDs 1–80)

Scope: every cached README for catalog IDs 1–80 was **skimmed** (headings, quickstart, stated interface); clones were code-reviewed only for IDs 2, 4, 14, and 383. No upstream code was executed and no API call was made. Claims in README-only entries remain claims, not verified capabilities.

## Findings

1. **A single Python decision-client seam is more transferable than adding providers/SDKs.** The official Python SDK has `AsyncTypeSafeClient` with per-client `RetryPolicy`, timeout, transport/http-client injection, and async context management ([client.py#L21-L56](https://github.com/typesafe-ai/typesafe-sdk-python/blob/0ffd094c72ed9445223060b24ffd7a56aa781fb4/src/typesafe_sdk/_core/client/aio/client.py#L21-L56)); `system_one` accepts named typed questions about JSON/text state ([client.py#L137-L176](https://github.com/typesafe-ai/typesafe-sdk-python/blob/0ffd094c72ed9445223060b24ffd7a56aa781fb4/src/typesafe_sdk/_core/client/aio/client.py#L137-L176)). Its retry defaults are bounded (two retries after initial), retry 408/429/5xx/connection/timeout by default, honor Retry-After, and impose a 30s total budget ([retry.py#L36-L85](https://github.com/typesafe-ai/typesafe-sdk-python/blob/0ffd094c72ed9445223060b24ffd7a56aa781fb4/src/typesafe_sdk/_core/retry.py#L36-L85), [retry.py#L100-L136](https://github.com/typesafe-ai/typesafe-sdk-python/blob/0ffd094c72ed9445223060b24ffd7a56aa781fb4/src/typesafe_sdk/_core/retry.py#L100-L136)).
   Caveat: these are SDK mechanics, not evidence that any job-enrichment judgment is accurate or calibrated.

2. **The comparison-adapter boundary is concrete and testable.** ID 2 separates provider-only single requests from schema/decode/retry ownership: `SyncProvider`/`AsyncProvider` protocols carry `request(...schema, structured)` and error translation ([base.py#L1-L8](https://github.com/typesafe-ai/system-one-adapter-python/blob/e1d4cc938204b22fc5a3c3aca7044072fe3f712d/src/system_one_adapter/providers/base.py#L1-L8), [base.py#L61-L100](https://github.com/typesafe-ai/system-one-adapter-python/blob/e1d4cc938204b22fc5a3c3aca7044072fe3f712d/src/system_one_adapter/providers/base.py#L61-L100)). It snapshots request/response/error attempts ([base.py#L126-L167](https://github.com/typesafe-ai/system-one-adapter-python/blob/e1d4cc938204b22fc5a3c3aca7044072fe3f712d/src/system_one_adapter/providers/base.py#L126-L167)) and puts document text in an explicitly untrusted prompt boundary ([`_client.py#L66-L94`](https://github.com/typesafe-ai/system-one-adapter-python/blob/e1d4cc938204b22fc5a3c3aca7044072fe3f712d/src/system_one_adapter/_client.py#L66-L94)).
   Caveat: the adapter manufactures/normalizes probability-shaped outputs; do **not** equate them with calibrated probabilities without a held-out scraper dataset.

3. **Semantic validation should preserve three states: accept, reject, and explicitly unavailable/uncertain.** zod-jev validates response shape even on HTTP 200, maps missing answers to `unavailable`, and uses a two-sided threshold so the middle band becomes `uncertain` ([judge.ts#L120-L161](https://github.com/jomatsu/zod-jev/blob/700bd256fe94541a2d21044027cc2dbf5036b396/src/judge.ts#L120-L161)); timeout/network/transient HTTP faults are also unavailable rather than acceptance ([judge.ts#L165-L225](https://github.com/jomatsu/zod-jev/blob/700bd256fe94541a2d21044027cc2dbf5036b396/src/judge.ts#L165-L225)). This aligns with exact/alias matching first: semantic judgment can only be a later, auditable fallback.
   Caveat: implementation is TypeScript/Zod and its threshold defaults are policy choices, not ready-made Python policy.

4. **Batch independent semantic questions but bound the payload.** zod-jev collects rule targets into one request and rejects oversized state/question payloads locally ([judge.ts#L84-L113](https://github.com/jomatsu/zod-jev/blob/700bd256fe94541a2d21044027cc2dbf5036b396/src/judge.ts#L84-L113)); its array path chunks according to max questions ([semantic.ts#L134-L180](https://github.com/jomatsu/zod-jev/blob/700bd256fe94541a2d21044027cc2dbf5036b396/src/semantic.ts#L134-L180)).
   Caveat: “latency almost unchanged” in README/comments was not benchmarked here; use actual scraper volume and provider limits.

5. **Make uncertainty thresholds operator-configurable and capture cost/identity.** Qualm’s client calls out that its default confidence is arbitrary and must be calibrated on the caller’s own data ([client.ts#L46-L66](https://github.com/qddegtya/qualm/blob/e1aacf6844f312ba95eb6a1bd26fad15575a7173/src/client.ts#L46-L66)); it returns model identity and token usage ([client.ts#L109-L129](https://github.com/qddegtya/qualm/blob/e1aacf6844f312ba95eb6a1bd26fad15575a7173/src/client.ts#L109-L129)). Its retry code retries only 429/5xx, honors Retry-After, uses jitter, and gives one overall deadline ([retry.ts#L22-L79](https://github.com/qddegtya/qualm/blob/e1aacf6844f312ba95eb6a1bd26fad15575a7173/src/retry.ts#L22-L79)).
   Caveat: Qualm is TypeScript and its Cloudflare unwrapping has a source comment to confirm on the first real call ([provider.ts#L53-L64](https://github.com/qddegtya/qualm/blob/e1aacf6844f312ba95eb6a1bd26fad15575a7173/src/provider.ts#L53-L64)); it is evidence of interface ideas, not a vetted dependency.

6. **Catalog screening result.** IDs 10–56 are mainly duplicate non-Python SDKs; IDs 59–74 are mainly local/self-hosted Jev-compatible servers; ID 75 is a broad gateway. Readmes alone do not verify compatibility, security, maintenance, calibration, or fit. For this Python scraper, the evidence supports a narrow internal adapter around one approved client, not SDK/provider proliferation. Operator confirmation should gate any new enrichment skill or semantic fallback.
